# 智能体 · 个人助理 & 游戏 NPC

一套引擎，两种用法：平时当**个人助理**，做游戏时当 **NPC** 的脑子。  
还能通过 HTTP 接口接进 Godot / Unity，并在浏览器里聊天。

核心就四件东西：**LLM + 工具 + 循环 + 记忆**。没有框架，代码短到能一口气读完。

## 安装 & 配置

```bash
pip install -r requirements.txt      # 实际只需 requests，通常已自带
cp .env.example .env                 # 填入你的 API key
```

### 用国内模型（推荐，直连不用梯子）

```bash
python providers.py                  # 看有哪些预设
python providers.py deepseek         # 一键切换，改好 .env 的地址和模型名
```

然后把 `.env` 里的 `OPENAI_API_KEY` 换成对应厂商的 key 即可。  
预设：**deepseek / kimi / qwen / glm / openai**。模型名可能会更新，报「模型不存在」时按官网当前名字改一行就行。

## 三种玩法

### 1. 命令行

```bash
python main.py                      # 个人助理
python main.py --npc blacksmith     # 铁匠 NPC
python main.py --npc innkeeper -v   # -v 用 macOS 语音念出来
python main.py --list               # 看所有 NPC
```

指令：`/quit` 退出，`/reset` 清空记忆，`/state`（NPC）看游戏状态。

### 2. 网页聊天

```bash
python server.py                    # 然后浏览器打开 http://127.0.0.1:8200
```

界面上可切换「个人助理 / 游戏 NPC」，左侧是**人物图像位**（大头像 + 名字 + 状态），聊天里每条消息带小头像。NPC 模式下能实时看到血量、金币、背包被对话改变。

### 换成你自己的美术

头像在 `web/avatars/`，一共 5 张：`assistant.svg`、`blacksmith.svg`、`innkeeper.svg`、`sage.svg`、`player.svg`。

替换两种方式：

1. **同名覆盖**：把同名 `.svg` 换成你自己的图（保持 SVG 格式最省事）。
2. **换文件名**：放一张 `blacksmith.png`，然后改 `characters.json` 里对应角色的 `avatar` 字段：

```python
"blacksmith": {
    "name": "老铁", "title": "铁匠",
    "avatar": "avatars/blacksmith.png",   # ← 改这里
    ...
}
```

> 想重新生成占位头像：`python make_avatars.py`  
> 建议用正方形图（比如 512×512），会被裁成圆形显示。

### 3. 接进游戏（Godot / Unity）

先启动 `python server.py`，游戏里通过 HTTP 调用：

```
POST /chat   {"session":"xxx","mode":"npc","npc":"blacksmith","message":"你好"}
          -> {"reply":"...","state":{"player_hp":60,"gold":100,"inventory":[]}}
```

- Godot 4：见 `game_clients/GodotNpc.gd`
- Unity：见 `game_clients/UnityNpcClient.cs`

关键点：**NPC 的工具直接改游戏状态**，所以对话能真的扣钱、给物品、回血——游戏循环读 `state` 就知道发生了什么。

## 互动：让对话真的改变生命值和金钱

这是整套东西的核心。NPC 手里有一份**服务端定死的价目表**，玩家的每次交易都会真的改游戏状态。

在 `characters.json` 里给每个角色配价目表：

```python
"blacksmith": {
    "goods":    {"铁剑": 50, "钢盾": 80, "皮甲": 60},          # 商品：买入进背包
    "services": {"修理装备": (10, "repair"),                    # 服务：(价格, 效果)
                 "磨刀": (5, "info")},
    ...
},
"innkeeper": {
    "goods":    {"红药水": 15, "干粮": 5},
    "services": {"住店一晚": (20, "heal:40")},                  # 回血 40
},
```

效果类型：`"heal:40"` 回血、`"repair"` 修理、`"info"` 只扣钱不给东西。

### 三层保险（防止模型乱来）

1. **价格服务端说了算** —— 模型只能传「要买什么」，传不了价格，`buy_item` 自己去价目表查。
2. **钱不够直接拒绝** —— `buy_item` / `buy_service` 会先校验金币，不够就返回「金币不足」，交易失败、状态不变。
3. **状态每轮注入** —— 通过 `context_provider` 把玩家的血量/金币/背包实时拼进 system prompt，NPC 才知道你兜里有多少钱。

### 接口会返回「变化量」

`/chat` 的响应里多了 `changes`，前端拿它做动画：

```json
{
  "reply": "嘿，钱货两清！铁剑拿好。",
  "state": {"player_hp": 60, "gold": 50, "inventory": ["铁剑"]},
  "changes": [
    {"kind": "gold", "delta": -50},
    {"kind": "item_add", "item": "铁剑"}
  ]
}
```

`changes` 里可能出现：`{"kind":"gold","delta":-50}`、`{"kind":"player_hp","delta":40}`、`{"kind":"item_add","item":"铁剑"}`、`{"kind":"item_remove","item":"..."}`。

游戏接入时，你只要读这个 `changes` 就能触发自己的动画/音效。

## 存档：一个角色一份，属于「你 ↔ 这个角色」

服务端每轮对话后都会把**完整上下文 + 游戏状态**写进 `saves/`：

```
saves/
├── npc_blacksmith.json     ← 你和老铁的记忆
├── npc_innkeeper.json      ← 你和老板娘的记忆
├── npc_sage.json
└── assistant.json          ← 你和助理的记忆
```

**一个角色只有一个存档**，跟浏览器会话无关 —— 换浏览器、清缓存、换电脑（把 `saves/` 拷过去），进度都还是同一份。

- 文件名 = `模式_角色.json`，纯本地 JSON
- 浏览器只用 `localStorage` 记住**当前角色**（`agent_char`），所以刷新后回到同一个角色
- **「清空记忆」只清当前角色**，其他角色不受影响
- 想全清：在存档面板里逐个删，或直接删 `saves/` 目录
- 想备份/搬家：点「存档」→「📦 整包备份」，或直接拷 `saves/`

> 早期版本按浏览器会话存（会出现好几个「老铁」）。服务启动时会自动合并成每个角色一份，保留最近的那次对话。

## 🕒 时间与天气（随现实而动）

头像那一排下面有一条很细的带子：

```
上午 11:21:00 | 10月22日 周四 | ☀️ 兰州 晴 11.6°C  体感 10.1° · 湿度 63% · 风 4.6 km/h
```

- **时间**：走你电脑的钟，每秒跳一次（不用联网）
- **日期**：月/日/周几，跨零点自动变
- **天气**：真实天气，来自 [Open-Meteo](https://open-meteo.com)（**免费、不用 API key**）
- **地点**：默认按公网 IP 猜（`ipinfo.io`），猜不到就用兰州
- **刷新**：天气 10 分钟拉一次；电脑睡眠唤醒后会补拉一次

### 想固定城市

在 `settings.json` 里加：

```json
{
  "disabled": ["chiaya"],
  "ambient": { "city": "兰州", "lat": 36.0611, "lon": 103.8343 }
}
```

`city` 只是显示名，`lat`/`lon` 才决定天气。

### 接口

```bash
curl http://127.0.0.1:8200/ambient
curl "http://127.0.0.1:8200/ambient?refresh=1"     # 强制刷新，忽略缓存
```

```json
{
  "ok": true,
  "now": "2026-10-22T11:20:20",
  "date": "10月22日", "weekday": "周四", "daypart": "上午",
  "loc": {"city": "兰州", "lat": 36.057, "lon": 103.8399, "source": "ip"},
  "weather": {"temp": 11.6, "feels": 10.1, "humidity": 63, "wind": 4.6,
              "code": 0, "text": "晴", "icon": "☀️", "is_day": 1},
  "magic": {"sense": 56, "level": "平稳", "power": 1.84, "slots": 3}
}
```

- 服务端缓存 10 分钟，不会每刷新一次页面就请求一次
- 天气接口挂了会先用上一次的数据顶着（标 `stale`），界面不会空着


## ✨ 魔力感应

左侧栏头像下面多了一行：**魔力感应**。它不是随机数，也不是存档里的固定值——
**由此刻真实的天气、湿度、温度、风和时辰算出来**，会随时间自己变。

```
✨ 魔力感应                    56
━━━━━━━━━━━━━━━━━━━━░░░░░░░░░
平稳 · 法术强度 ×1.84 · 可放 3 个
```

| 感应值 | 等级 | 法术强度 | 可放法术 |
|---|---|---|---|
| ≥85 | 澎湃 | ×2.28~2.5 | 4 个 |
| 65~84 | 充沛 | ×1.98~2.26 | 3~4 个 |
| 45~64 | 平稳 | ×1.68~1.96 | 2~3 个 |
| 25~44 | 微弱 | ×1.38~1.66 | 2 个 |
| <25 | 枯竭 | ×1.0~1.36 | 1 个 |

### 怎么算的

基准 45 分，再按真实条件加减：

| 因素 | 影响 |
|---|---|
| **天气** | 雷暴 **+28**；雾 **+18**；雪 **+14**；雨 **+12**；阴 +6；晴 0 |
| **湿度** | 每偏离 50% 一个点 **±0.18**（越潮越通灵） |
| **温度** | 10~24°C **+6**；0°C 以下 −8；5°C 以下 −4；32°C 以上 −7 |
| **风** | 10~30 km/h **+4**；超过 45 km/h **−6** |
| **时辰** | 子时（0~1 点）**+9**；正午（12 点）**−6**；夜里普遍加分 |

最后夹到 0~100。所以：

```
晴天 15°C 湿度 63% 微风  → 48（平稳，×1.72，2 个）
雷暴  9°C 湿度 92% 有风  → 80（充沛，×2.20，4 个）
暴晒 36°C 干燥 大风      → 22（枯竭，×1.33，1 个）
```

### 角色也知道

这一行会进所有角色的上下文：

```
【魔力】魔力感应 56/100（平稳），法术强度 ×1.84，此刻可放 3 个法术
```

问老者「现在能放几个法术」，他会照着答：

```
你：此刻的魔力感应如何？我能放几个法术？
老者：（抬手试了试风）平稳得很，三道法术，够用。
```

### 存储

**不存**。它是从 `/ambient` 现算的派生值——天气一变、时辰一到，自己就变，
不需要存档，也不会和真实天气对不上。

```json
"magic": { "sense": 56, "level": "平稳", "power": 1.84, "slots": 3 }
```

### 角色知道现在几点、外面什么天

发给模型的上下文里多了这么一段：

```
【当前实时状态 · 每轮刷新】
现在是 10月22日 周四 上午 11:46；外面中雨，9.0°C（偏冷），风不大，湿度 92%，天已经黑了
外头下着雨，没人愿意在外面久站；夜里了，街上没什么人
玩家：旅人，生命值 100/100，金币 50，背包 铁剑
（这些是背景，别生硬罗列，也别每句都报时间天气。但时间天气会影响人怎么做事——
天冷、下雨、夜里，你手上的活和说话的样子自然跟着变，不用等玩家提起。）
```

**注意：没有「下雨 → 铁匠收摊」这种角色规则表。** 给的是事实（几点、什么天、
体感冷暖、街上什么状况），怎么做是这个角色的常识。

数字都翻译成了人话，省得模型自己去想 9°C 算不算冷：

| 原始 | 给模型看 |
|---|---|
| `temp: 9.0` | `9.0°C（偏冷）` |
| `wind: 18.0` | `风不大` |
| `is_day: 0` | `天已经黑了` + `夜里了，街上没什么人` |
| `code: 63` | `中雨` + `外头下着雨，没人愿意在外面久站` |

### 凭什么说它真的会跟着变

把缓存改成「雨夜 9°C」跑了一遍（没加任何角色专属规则）：

```
你（对老铁）：在忙啥呢？
老铁：嘿，炉子上燎着块钢，正回火呢。这鬼天气下着雨，冷得跟冰窖似的，
      炉边倒还算暖和——进来暖暖手？

你（对老板娘）：今儿还开张吗？
老板娘：哎哟，这雨下得跟倒水似的，你还站在门口淋着？来来来，快进来，
        门我给你带上——开张，天天开张，炉子就没灭过。
        （拿抹布把靠炉边的桌子又擦了一遍）坐下说……喝口热的先。
        住一晚二十，含一碗热汤，红药水十五，干粮五块。
```

同一个「下雨了」，铁匠往炉边让，老板娘往店里拉，还顺手把价目报了一遍 ——
不是执行规则，是各自的身份在起作用。

换成晴天再问一次，就不会硬提天气：

```
你（对老板娘）：外头下雨了吗？我该带伞不？
老板娘：没下雨！大晴天的，日头晒得人睁不开眼，带伞反倒累赘。
        不过北风刮得紧……带件厚实点的褂子比伞实在。
```

生效范围：

| 场景 | 是否带【此刻】 |
|---|---|
| 一对一聊天 `/chat` | ✅ 每个 NPC 每轮刷新 |
| 群聊 `/group/chat` | ✅ 每个角色发言前 |
| 对戏 / 对战 | ✅ 提示词里带 |
| 小助 | ✅ 且说明「这是本机所在地」 |

```js
const THEME_TERMS = {

function terms(){ return appearance.theme === 'cyber' ? THEME_TERMS.cyber
                                                     : THEME_TERMS.default; }
```

- `localStorage` —— 刷新时先按缓存的画一帧，不会闪

### 页面背景

「外观」→ 页面背景 → **＋ 上传图片 / 动图**（jpg / png / webp / **gif**）。

- 静图 ≤12MB，**动图 GIF ≤30MB**，GIF 会真的动（CSS 背景支持动画）
- 带「动图」标记的缩略图就是 GIF

- 图片存在 `web/bg/`，进整包备份
- 动图会持续解码，特别大的 GIF 会让风扇转起来，建议 5MB 以内
- 列表里可以点选、也可以点 `×` 删掉
- **暗化**（0~95%）和**模糊**（0~24px）只作用于背景，不影响文字和气泡
- 选「无背景」回到纯色

### 毛玻璃

有背景图时，面板会变成半透明 + 背景模糊透出来：

| 控件 | 作用 |
|---|---|
| `毛玻璃：开 / 关` | 侧栏、顶栏、时间天气条、输入栏、消息气泡、弹窗 |
| `玻璃模糊` 0~30px | 玻璃的磨砂程度（越大越糊，字越清楚） |

```
不开毛玻璃            开毛玻璃
┌──────────┐         ┌──────────┐
│ 实心面板  │         │ 背景透出来 │
└──────────┘         └──────────┘
```

实现是 `backdrop-filter: blur() saturate()` + `color-mix()` 半透明底色：

```css
body.has-bg.glass aside,
body.has-bg.glass header{ 
  background: color-mix(in srgb, var(--panel) 64%, transparent);
  backdrop-filter: blur(var(--glass-blur, 16px)) saturate(1.35);
}
```

- 只对**有背景图**时生效（纯色背景没有东西可透，开了没区别）
- 气泡用 78% 不透明度，保证文字对比度
- 弹窗用 72% + `blur(22px)`，打开时像隔着一层磨砂玻璃
- 老浏览器不支持 `color-mix` / `backdrop-filter` 时自动退回实心面板

```json
"appearance": {
  "theme": "ink",
  "bg": "bg/bg_20261022_130514.png",
  "dim": 0.62,
  "blur": 3,
  "glass": true,
  "glass_blur": 18
}
```

## Markdown 渲染

回复里的 markdown 会被渲染出来，不再是原始符号：

| 语法 | 效果 |
|---|---|
| `**粗体**` / `*斜体*` / `~~删除线~~` | 粗 / 斜 / 删除线 |
| `` `行内代码` `` | 灰底小方块 |
| 三个反引号包起来的代码块 | 独立代码框，保留换行 |
| `- 列表` / `1. 列表` | 带圆点 / 编号 |
| `# 标题` `## 标题` `### 标题` | 三级标题 |
| `> 引用` | 左侧竖线引用 |
| `[文字](https://...)` | 链接（只放行 http/https） |
| `---` | 分割线 |

**安全**：先对整个文本做 HTML 转义，**再**解析 markdown —— 所以模型输出 `<script>` 之类的
东西只会被当成文字显示，不会被执行。链接也只允许 `http/https`。

> 用户自己发的消息不做 markdown 渲染，原样显示。

## 角色管理：停用 / 抹除 / 拖动排序

点头部「**存档**」按钮，弹窗上半部分是角色管理。

**拖动排序**：每行最左边有个「⠿」手柄，按住往下拖就能调整顺序，
松手会自动保存（提示「角色顺序已保存」）。顶部那头像栏会同步跟着变。

- 顺序存在 `characters.json` 的数组顺序里
- 拖到某一行的**上半部分** = 插到它前面；**下半部分** = 插到它后面
- 拖拽时会有蓝色横线提示落点

每个角色有三个按钮：

| 按钮 | 效果 | 存档 | 头像 | 代码 |
|---|---|---|---|---|
| **音色** | 调这个角色的嗓音 | 不动 | 不动 | 不动 |
| **停用** | 从角色列表隐藏，随时可开回来 | ✅ 保留 | ✅ 保留 | 不动 |
| **抹除** | **彻底删除**，无法撤销 | ❌ 删除 | ❌ 删除 | ❌ 从 `characters.json` 移除 |

**抹除**做的事（顺序执行，任一步失败也不影响其他步）：

1. **先备份到回收站** `erased_last.json`（角色数据 + 头像 + 存档）
2. 从 `characters.json` 里删掉这一条（**纯数据操作，不碰任何 Python 代码**）
3. 删掉该角色的存档 `saves/npc_xxx.json`
4. 删掉头像 `web/avatars/xxx*.svg`
5. 在 `settings.json` 的 `deleted` 里记一笔兜底，确保重启后也不会再冒出来

### 撤销上次抹除（单槽回收站）

弹窗里有一栏「**回收站 · 仅保留最近一次抹除**」：

- 只保留**最近一次**抹除。再抹除一次，上一次的就**永远丢弃**，不会累积。
- 点「撤销抹除」→ 角色数据插回 `characters.json`（原位置）、头像恢复、存档恢复，并自动重载（不用重启服务）。
- 撤销成功后回收站立即清空，不能重复撤销。

所以正确用法是：**抹错了马上撤销**；隔了一次就不能再回头了。

「停用」的记录在 `settings.json` 的 `disabled` 里，抹除的记在 `deleted` 里：

```json
{ "disabled": ["chiaya"], "deleted": [] }
```

> ⚠️ 抹除后只有**一次**后悔机会。想长期收起某个角色，用**停用**；  
> 想留后路，抹除前先点「📦 整包备份」。

### 🎙️ 角色专属音色

每个角色可以有自己的**音色 + 语速 + 音高**，说话时就用自己的嗓子：

| 角色 | 音色 | 语速 | 音高 |
|---|---|---|---|
| 老铁（铁匠） | Reed | 175 | -6（低沉） |
| 老板娘 | Flo | 205 | +4（快、亮） |
| 老者 | Grandpa | 145 | -3（慢） |
| 千绫 | Meijia | 160 | +1 |
| 莫妮卡 | Shelley | 175 | +2 |
| 心 | Sandy | 165 | +3 |
| 西北师范 | Tingting | 185 | 0 |

**怎么调**：角色管理那一行点「**音色**」→ 选音色、拖语速/音高 → 「试听」→ 「保存」。

- 「**清除**」= 这个角色改回用默认音色
- 配置存在 `characters.json` 的 `voice` 字段里：

```json
"voice": {"name": "Reed (中文（中国大陆）)", "rate": 175, "pitch": -6}
```

**音高是怎么做到的**：macOS 的 `say` 支持嵌入式指令，给文本前面加 `[[pbas +6]]`
就能整体升/降调。实测过：同一句话升 12 个半音后，波形过零率从 2714 升到 3214。

> 优先级：**角色自己的配置 > 默认音色**（自动选第一个中文 zh_CN 语音）。
> 助理（小助）没有角色配置，用默认的。

### 🔈 声音从哪出来（重要）

内嵌浏览器（比如本应用的预览面板）经常**拿不到音频输出**：实测 `play()` 成功、
`currentTime` 也在走、音量 1、没静音，但就是听不到。

所以播放走**双路径**：

```
① 先请求 POST /speak → 服务器用 afplay 直接在系统扬声器上播   ← 本地最可靠
② 服务器放不了（非 macOS）→ 退回浏览器 <audio> 播放             ← 远程场景
```

生成一版音频大约 0.5~3 秒（`say` + `afconvert`），所以点完会有个短暂延迟，不是没反应。

好处：**游戏客户端也能直接复用这些接口**（Godot / Unity 里放个 AudioStream 就行）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/voices` | 列出系统中文语音（`?all=1` 返回全部） |
| POST | `/tts` | 生成音频**返回**给浏览器 `audio/wav` |
| POST | `/speak` | 生成音频并**在服务器本机播放**（返回 JSON） |
| POST | `/set_voice` | 设/清角色音色 |

`/tts` 和 `/speak` 接受同样参数：`{text, key, voice, rate, pitch, fallback_voice}`。
传 `key` 就用该角色的音色。

> 只支持 macOS（`say` + `afconvert` + `afplay`）。非 macOS 返回 501。

> 单张上限 8MB。

### 命名规则（知道一下就行，不用记）

表情靠「在扩展名前插 `-表情`」推导，**基准名来自 `avatar` 字段**（不是角色 key）：

```
avatar = "avatars/hsin.svg"        →  开心时找 hsin-happy.svg
avatar = "avatars/my-girl.png"     →  开心时找 my-girl-happy.png
```

三种表情：**不带后缀 = 中性**，`-happy` = 开心，`-angry` = 生气。

**缺失的表情图会自动退回中性图**，不会裂。

### 谁决定用哪个表情

1. **NPC 主动表态** —— 调用 `show_expression` 工具（可选 neutral / happy / angry）
2. **服务端自动猜** —— NPC 没表态时，买卖成功 → happy，没别的变化 → neutral

### 想加第 4 种表情（比如「难过」）

前端是通用的，改两处就行：

1. `tools.py` 的 `show_expression` 里，白名单和 enum 加上 `"sad"`
2. 准备 `xxx-sad.svg`（或在网页上传到新增的槽位）

> 想让它自动触发，再去 `server.py` 的 `infer_mood` 加规则。

## 想让角色更有特色？

**核心原则：少写形容词，多写具体的东西。**

模型对「豪爽、直率」这类词几乎无感，但对「左臂有道疤，是十年前赶活留下的」这种具体细节会照做。
所以每个角色除了基础字段，还有这些：

| 字段 | 作用 | 例子 |
|---|---|---|
| `history` | **一段具体的过去**（有事件、有代价） | 「十六岁接了爹的炉子……十年前赶活淬火走神，左臂留了道疤，从此再不接急活」 |
| `catchphrase` | 口头禅 | 「急啥？铁得慢慢打。」 |
| `quirk` | 小动作 / 身体习惯 | 「说话时用拇指蹭围裙上的灰」 |
| `loves` / `hates` | 明确的好恶（不是「善良」） | 「好钢、烈酒、识货的人」/「赊账的、磨磨唧唧的」 |
| `secret` | 不愿提的事（制造深度） | 「左臂那道疤，还有那一炉报废的活」 |
| `never` | 绝不会做的事 | 「不说软话，也不承认自己老了」 |
| `samples` | **2~3 组示例台词**（few-shot，效果最大） | 见下 |

```json
"samples": [
  ["这剑多少钱？", "五十。嫌贵？隔壁有卖木头的。"],
  ["能不能便宜点？", "嘿，我这铁又不长腿，自己会跑？不买拉倒。"]
]
```

> **`samples` 是性价比最高的一项** —— 两句话就能把语气、句长、态度全定下来。

### 效果

同一个问题「你觉得这村子怎么样？」问五个人：

| 角色 | 回答 |
|---|---|
| 老铁 | 穷是穷了点，可炉火旺、酒够烈，住着踏实。就是事儿多，狼闹得凶 |
| 老板娘 | （一口气 111 字，末尾「**坐下说，站着话不落地**」） |
| 老者 | **（望向村口）**住得久了，才尝得出它的味道。 |
| 猎人 | **人太多。山里好。** |
| 西北师范 | 村子不大，人心却实。**老铁**打铁一锤是一锤…… |

### 再加三个杠杆

1. **`verbosity`**：`terse` / `normal` / `chatty` —— 直接决定话多话少（猎人 6 字，老板娘 111 字）
2. **`voice`**：音色 + 语速 + 音高（猎人是低沉慢，老板娘是快亮）
3. **`relations.json`**：让他们互相提到对方，世界就连起来了

## 🧩 每个角色用不同的模型

角色管理那一行点「**模型**」，可以给单个角色指定另一套模型 —— 比如让主角跑好模型、配角跑便宜的。

```
预设      [ DeepSeek ▼ ]     ← 一键填地址和模型名
接口地址  https://api.deepseek.com/v1
模型名    deepseek-chat
API Key   ••••••••（已保存，留空 = 不修改）

          [清除]  [测试连通]  [保存]
```

内置预设：**DeepSeek / Kimi / 通义千问 / 智谱 GLM / OpenAI / 自定义**。

- **测试连通**：会真的发一句「只回复两个字：通了」过去，成功会提示 `连通 ✅ deepseek-chat → 通了`
- **清除**：这个角色改回用全局模型
- **保存后立即生效**（会丢掉该角色的旧会话，不用重启）

### 存储与安全

| 内容 | 存在哪 | 进整包备份吗 |
|---|---|---|
| `base_url` / `model` | `characters.json` 的 `model` 字段 | ✅ 会 |
| **`api_key`** | **`model_keys.json`**（单独文件） | ❌ **不会** |

这样设计是因为整包备份会包含 `characters.json` —— 如果 key 写在那里，一备份就跟着走了。

> `model_keys.json` 在 `backup.py` 的包含列表之外，所以整包备份天然不会带它。
> 换电脑后需要重新填一次 key（模型和地址会跟着备份过去）。

### 未配置时的行为

- 角色**没配** `model` → 用全局那个（`.env` 里的）
- 配了但**没填 key** → 用全局的 key（跨厂商时会报 401，补上就行）


- 统计到 `usage_stats.json`，和对话存档分开（清空记忆不会影响它）

### ④ 对战（两种模式）

对戏面板顶部：**🎭 对戏 / ⚔️ 对战**，对战里还有个「**真打（掉血）**」开关。

**A. 叙事型（默认）** —— 纯表演，不改数值，让模型自由发挥：

```
老者    （负手侧身，让过一支试射的箭）年轻人，弓是好弓，可惜拉弦的手太急。
猎人    （皱眉搭箭，第二发贴地而去）试试就试，别废话。
旁白    箭钉在老者脚前半寸，入土三分。
```

**B. 真打（勾上「真打」）** —— 会真的掉血：

```
结果  老铁 胜（猎人 1/90，老铁 35/120）
```

## ⚔️ 真打是怎么算的

**架构：Python 算账，模型只写描写。**

```
① 引擎（server.py 的 _run_duel）
   看速度决定先手 → 算伤害 → 判胜负 → 写回血量
② 把算好的回合表喂给模型 → 它只负责写成打斗场面
③ 模型不能改结果（提示词里写死了，且返回时用引擎的结果覆盖）
```

**伤害公式**：

```
伤害 = max(1, atk - def*0.45 + 随机(-2~3))
暴击 = 12% 概率，伤害 ×1.6
先手 = spd + 随机(0~5) 更高者先动
回合上限 12，超时按剩余血量百分比判
```

**角色属性**（`characters.json` 的 `stats`）：

| 角色 | HP | 攻 | 防 | 速 |
|---|---|---|---|---|
| 老铁 | 120 | 18 | 10 | 5 |
| 猎人 | 90 | 15 | 6 | **12** |
| 老者 | 85 | 11 | **12** | 6 |
| 老板娘 | 70 | 6 | 5 | 7 |
| 西北师范 | 60 | 4 | 4 | 5 |

所以猎人先手快、老铁皮厚输出高、师范基本打不过任何人 —— **数值也在讲故事**。

|---|---|

| token 花费 | `usage_stats.json` |
| 完整战报文字 | ❌ 不存（只在界面显示） |

## 👥 群聊：几个角色真正互相说话

顶部「👥 **群聊**」→ 勾 2~6 个角色 + 可选话题 → 开聊。

```
👥 群聊   老铁、猎人、老者 · 今晚谁去山上看一眼

老铁  嘿，别看我，炉子还热着呢，我这把老骨头可经不起夜里上山。
      猎人那小子脚程快，让他去。
猎人  （瞥了眼老铁，又往山那边抬了抬下巴）我去。谁欠我一副箭头，明早补上。
旅人  @老者 您觉得该派谁？
老者  （望了眼山口，慢悠悠地）谁去都行，只看谁心里没鬼。
老铁  嘿，这话里有话啊。我这铁砧天天摆在院里，谁心里有鬼谁没鬼，
      还能瞒得过打铁的？
```

每条消息都带说话人的头像：角色用 `characters.json` 里配的头像，玩家用
`web/avatars/player.svg`，右侧显示。顶部标题栏也排着在场成员的小头像，
选人时的角色按钮同样带头像 —— 和主聊天界面的视觉一致。

### 和对戏的区别（重要）

| | 🎭 对戏 | 👥 群聊 |
|---|---|---|
| 谁在写 | **一个模型**写所有人的台词 | **每个角色各调一次自己的模型** |
| 上下文 | 它同时看到两个人的人设 | 每人只看到「在场的人 + 刚才的对话」 |
| 像不像真人 | 容易写成书面剧本 | 会抢话、会接梗、会互相拆台 |
| 成本 | 1 次调用 | 每轮每人 1 次 |
| 模型配置 | 用 B 的模型 | **各用各的**（老铁仍是 deepseek-flash） |

群聊里角色之间**没有直接通信通道** —— 它们是通过**共享的对话记录**交流：轮到谁，谁就把前面所有人说的话当上下文读一遍，再说自己那句。这就是"多智能体"最简单也最稳的做法（总线式，不搞点对点）。

### 玩法

| 操作 | 效果 |
|---|---|
| 开聊 | 建群，并先让 2 个角色开口 |
| 发送 | 你以「旅人」身份插一句，默认 2 个角色接话 |
| `@老者` | 点名，被点到的人先说，然后继续轮流 |
| 🔁 自动聊 | **开关**：开了就一直自己聊下去，直到你关掉 |
| 结束 | 回到选人界面（这场对话已存档） |
| 继续之前的群 | 下拉选历史群聊，接着聊 |

### 🔁 自动聊：不关就一直聊

群里那个「🔁 **自动聊：关 / 开**」按钮是**持续开关**，不是"聊 3 轮"。

```
关掉时                          开着时
🔁 自动聊：关         →         🔁 自动聊：开
                                … 自动聊中 · 已完成 14 轮
                                （说一句、停 0.7 秒、下一个人接）
```

**它怎么跑**

```
点开 → 第 1 轮：轮到的人说话 → 等 0.7 秒 → 第 2 轮 → …… 一直循环
```

- 每轮 = 1 次 `/group/chat`（`rounds: 1`），说一句显示一句，不用等一整段
- 你和它同时说话也没事：所有请求排成一条队，**自动聊会等你的话发完再继续**
- 顶部会显示 `自动聊中 · 已完成 N 轮`，心里有数

**什么时候会自己停**

| 情况 | 结果 |
|---|---|
| 你点一下按钮 / 关闭面板 / 点「结束」 | 立刻停（当前那一轮会跑完） |
| 模型出错、或没人接话（返回空） | 自动停，提示「没人接话了」 |
| 一直不关 | **一直聊**，没有轮数上限 |

> ⚠️ 它会一直烧 token：3 个角色大约每 2 秒一轮，一轮约 1k token。
> 3 个角色聊 10 分钟 ≈ 900 次调用、约 90 万 token。放着过夜记得先关掉。


- 每个房间最多留 200 条
- 群聊**不进**单个角色的 1:1 记忆（免得把 1:1 存档灌满）；想让它记住，复制一句到聊天里就行
- 消耗记进「模型用量」，显示为 `group|g_xxx`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/group/create` | `{"members":["a","b"],"topic":"...","name":"..."}` |
| POST | `/group/chat` | `{"id","message":"可选","rounds":1}` — 返回本轮新说的话 |
| GET | `/group/list` | 最近的群（摘要） |
| GET | `/group?id=g_xxx` | 一个群的完整对话 |
| POST | `/group/delete` | `{"id"}` 删群 |

> `rounds` 最大 8，但一次请求里跑 8 轮会很慢（串行调用），
> 前端是逐轮发请求，说一句显示一句 —— 自动聊开关就是这么循环的。

## 📞 语音通话

顶部「📞 **通话**」→ 直接说话，不用打字。

```
                     ╭──────────────────╮
                     │ 嘿，八成是炭受潮了… │  ← 角色说的话（气泡）
                     ╰───────┬──────────╯
        ╭─────────────╮      │
        │             │◀─────╯
        │   [ 老铁 ]  │   ← 呼吸光环
        │             │
        ╰─────────────╯
             老铁
          正在说…
     你说：今儿炉子火不旺

            [ 挂断 ]
```

**角色一开口，文字就出现在头像右上角的气泡里**，不用回头翻聊天记录。
气泡最多显示 190 字（按标点收尾），说完 3.6 秒自动收起；太长的回复
仍然完整留在聊天区。

### 怎么跑

```
你说话 ──► VoiceCall.app 录音（自动断句）
       ──► faster-whisper 转文字
       ──► /chat（正常的人设、记忆、工具）
       ──► say 合成 ──► 本机扬声器
       ──► 播完再听下一句（循环到挂断）
```

- **自动断句**：说完停顿 1 秒就发出去，不用按键
- **不会自己听自己**：播放是阻塞的，念完才开始录
- **记忆照常**：走的是同一个 `/chat`，聊过的话会进这个角色的存档
- **表情/状态照常**：说话时头像、血量、金币该变还在变
- **气泡同步**：角色说的那句话同时出现在头像右上角（带小尾巴的对话气泡）

### 为什么录音在服务器，而不是浏览器

内嵌预览窗口没有麦克风权限（`getUserMedia` 直接报 `NotAllowedError`），
而且浏览器录音还要处理采样率、断句。放服务器上：

- 用 macOS 原生 `AVAudioEngine` 录，音质稳定
- 浏览器只负责显示，手机/别的电脑连过来也能用
- 代价：**声音从这台 Mac 的麦克风进、扬声器出**

### 第一次用要准备两样

**① 语音识别引擎**（一次性）

```bash
# 国内建议走镜像，直连 PyPI 很慢
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple faster-whisper zhconv
```

> `zhconv` 用来把 Whisper 偶尔冒出来的繁体转成简体，很小，几十 KB。

默认用 `small` 模型（中文够用，约 460MB），第一次通话自动下载。
模型也走国内镜像（`.env` 里已经配好）：

```bash
HF_ENDPOINT=https://hf-mirror.com
```

> 装完如果发现 `transformers` / `tensorflow` 报错，是 pip 顺手把
> `huggingface-hub` 升到了 2.x。降回来即可（不影响语音）：
>
> ```bash
> pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
>     "huggingface-hub<1.0" "protobuf<5"
> ```

想换模型大小：

```bash
export WHISPER_MODEL=base     # 更快更小，中文弱一点
export WHISPER_MODEL=medium   # 更准，约 1.5GB
```

**② 录音助手**（仓库里已编译好，改过源码才需要重编）

```bash
cd assistant_agent/voice_call && ./build.sh
```

> 首次运行 macOS 会弹「VoiceCall 想访问麦克风」，点允许。
> 这个 App 是本地临时签名的，不上传任何东西。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/call/warm` | 后台加载语音模型（首次下载） |
| GET | `/call/info` | 模型状态：`idle` / `ready` / `missing` |
| POST | `/call/listen` | 录一句并转文字 `{text, status, ms}` |
| POST | `/call/stop` | 立刻停掉正在录音的进程（挂断/关页面时调） |
| POST | `/call/stop_speak` | 打断正在播放的语音（返回 `{stopped}`） |
| POST | `/speak` | 加 `"wait": true` 会等播放完才返回（通话用） |

```bash
curl -X POST http://127.0.0.1:8200/call/listen -d '{"max":12}' \
     -H 'Content-Type: application/json'
# {"ok":true,"text":"今儿炉子火不旺","status":"ok","ms":2310}
```

### 实测（真的打通了）

用系统 TTS 从扬声器放一段话，让麦克风听进去：

```
你说：老铁 今天炉子火不忘 你帮我看看是咋回事 我这铁块烧了半天 也不红
      是不是没炭受炒了

老铁：嘿，八成是炭受潮了，要么风箱漏气，风口堵了！先把炭翻出来晒晒，
      风嘴捅通，火自然就蹿上来——急啥？铁得慢慢打。
```

识别有个把字不准（“旺”听成“忘”、“煤炭”听成“没炭”），但**意思到了**，
角色照样接得住——这正是它该干的事。

想更准就换模型：

```bash
export WHISPER_MODEL=medium    # 约 1.5GB，中文明显更准，慢一点
export WHISPER_MODEL=large-v3  # 最准，CPU 上偏慢
```

另外会给识别引擎喂**热词**（角色名 + 炉子/煤炭/客栈/铁砧…），
比裸跑少犯「炉灯火」「围探」这种错。

### 不会「偷偷占着麦克风」

通话是最容易出这种事的：面板关了，但后台还在录。四道闸：

| 闸 | 作用 |
|---|---|
| 前端巡检（3 秒） | 面板不可见就立刻停，并调 `/call/stop` |
| 关页面 / 刷新 | `pagehide` 时尽力发一次 `/call/stop` |
| 服务端单实例锁 | 同时只允许一段录音；开新录音前先清掉残留进程 |
| 录音助手看门狗 | 不管卡在哪，`max + 4` 秒后强制退出 |

> 如果你在后台标签页里**开着通话面板**，它当然会继续听——那是通话本身。
> 但只要面板收起、页面关掉、或者进程卡住，都会在几秒内松手。


### ⏹ 打断

**通话里**：角色正在说话时，底部会冒出「打断」按钮，按 **空格** 也行。

```
        [ 打断 ⏹ ]  [ 挂断 ]
              ↑ 点一下
        → 扬声器立刻停
        → 状态变回「正在听…」
```

**文字聊天里**：发送后按钮变成「停止」，点了就不再等：

```
你：讲一个很长很长的故事
老者：（你打断了他，这句没听完）
```

实现：

| 层 | 做法 |
|---|---|
| 播放 | 服务端用 `Popen` 起 `afplay` 并记下进程，`/call/stop_speak` 发 SIGTERM |
| `/speak` | 被打断时返回 `interrupted: true`，前端据此继续下一轮 |
| 文字 | `AbortController` 中断 `/chat` 请求，气泡改成「（你打断了他…）」 |

> 文字打断只是**不等了**：服务端仍会把这句生成完并存进历史，下次读档能看到完整回复。
> 语音打断是**真停**：`afplay` 进程被杀，声音立刻断。

### 已知限制

- 挂断时如果刚好在录音，麦克风还会多录几秒才释放（那一句会丢弃）
- 一次最多录 12 秒，8 秒没人说话就自动放弃这一轮
- `small` 模型纯 CPU 大约 1 秒出一句（M 系列芯片更快）；`medium` 约 3~5 秒
- 只支持 macOS（录放都靠系统能力）


## 🪄 法术系统（cast_spell）

魔力感应不是摆设——它决定角色能放几个法术、每个有多疼。

### 谁会法术

| 角色 | 法术 |
|---|---|
| 老者 | 火星诀（1 位·伤害）、安魂咒（1 位·治疗）、起雾（2 位·场面） |
| 老板娘 | 灶火（1 位·伤害）、热汤（1 位·治疗） |
| 猎人 | 鹰眼（1 位·场面） |
| 老铁 / 西北师范 | 不会（铁匠靠炭和锤子） |

数据在 `characters.json` 的 `spells` 字段，法术本身在 `spells.json`，都能改。

### 机制

```
玩家：老者，猎人抢了我的东西，用火星诀打他
  ↓ 模型调用 cast_spell(spell="spark", target="hunter")
  ↓ 服务器：查法术 → 查法术位 → 算伤害 → 改血量 → 扣位
  ↓ 返回：{"ok":true,"roll":23,"hp_after":44,"slots_left":0}
  ↓ 模型照着这个数字说：
老者：（雾里火星一亮，二十三伤）够了。他退了，你还追么？
```

**伤害永远由代码算**，模型只负责描述。它想吹也吹不出 999。

### 数值

```
法术位上限 = 1 + 魔力感应 // 25          （1~5，跟天气走）
伤害/治疗 = 基础值 × 法术强度 × 随机(0.9~1.1)
```

当前感应 57 → 强度 ×1.85：

| 法术 | 基础 | 实测 |
|---|---|---|
| 火星诀 | 12 | 23 伤 |
| 热汤 | 14 | 24 血 |

### 法术位

- 每次施法扣 `cost`（1 或 2）
- **每 10 分钟自动回 1 个**，最多回到上限
- 一轮对话最多施法 1 次（防止模型上头连发）

侧栏实时显示：

```
🪄 法术位  ● ● ○  2/3
```

### 拒绝的情况

| 情况 | 返回 |
|---|---|
| 不会这个法术 | `法术位不够` / `不会「xxx」` |
| 法术位不足 | `法术位不够（剩 0，需要 1），得等一会儿` |
| 同一轮第二次 | `这一轮已经施过法了，先歇口气` |
| 对玩家伤害 | 最低留 1 血（打服不打杀） |

角色会按自己的性格说出来：

```
（法术位 0 时）
老者：（摊手，火星在指尖灭了）空的。法术位空了，就得等。

（老铁被要求施法）
老铁：火星诀？老子这手艺靠的是炭和锤子，不会那些花里胡哨的玩意儿。
```

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/chat` | 施法在这条链路里，模型自己调工具 |
| GET | `/slots?npc=sage` | `{left, max, spells:[...]}` 侧栏用 |

### 已知边界

- 只有 NPC 会施法，玩家还没有施法面板（那是方案 B）
- 没有元素相克、范围、吟唱时间
- 伤害与 `/battle` 是两套公式，暂时各算各的

```
│ 今晚村口点篝火，各家带一样吃的来… │
```

实测：

```
你：今晚村里有什么事吗？
老板娘：坐下说——今晚村口点篝火，天黑就点，各家带一样吃的去。
        我这店里就出两锅汤，一锅咸的一锅甜，年年都这样。
        老铁肯定来，欠着我酒钱也不好意思空手；猎人兴许带着野味……
```

### 为什么不用手动通知每个角色

公告写进 `world_events.json`，带 `kind: "announcement"` 标记：

```json
{"t": "2026-10-24T16:21:00",
 "text": "今晚村口点篝火，各家带一样吃的来，天黑就点。",
 "kind": "announcement"}
```

然后拼进三类上下文：

| 场景 | 注入内容 |
|---|---|
| 一对一 `/chat` | `【村公告】…`（24 小时内最新一条） |
| 群聊 `/group/chat` | `【村公告】…`，没有就写「今天没有村公告」 |
| 小助 | `【村公告】…` |

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/announce` | `{"text":"..."}`，最长 200 字 |
| GET | `/announcements` | 最近 10 条公告（倒序取，前端再反一次） |

### 边界

- 只注入**最近 24 小时**内的最新一条；过期自动不提
- 公告不覆盖角色已有的记忆，只是多一条「村里的事」
- 没有删除接口（要删直接改 `world_events.json`）

## 记忆机制：只发最近 N 轮，老的压成一句话

**完整历史永远存本地**，但发给大模型时做了裁剪：

```
存档文件（saves/npc_xxx.json）
├── messages          ← 完整历史，一条不丢
├── summary           ← 老对话压成的一句话
└── summarized_upto   ← 压到第几条了
```

每次对话时，真正发给大模型的只有：

```
[system]  角色人设 + 实时状态（金币/血量）
[system]  【你对玩家过去的记忆（摘要）】阿飞买过铁剑，欠老板娘20金。
[user]    最近 memory_turns 轮对话（原文）
```

**效果**：

- 聊 500 轮也不会撞上下文上限 —— 因为只发最近 20 轮
- 花费不随对话变长而增长 —— 每轮发的量是固定的
- 但角色**仍然记得**早期的事 —— 靠那句摘要

**三个可调参数**（每个角色独立，在 `characters.json` 里）：

| 字段                | 默认     | 作用                                 |
| ----------------- | ------ | ---------------------------------- |
| `memory_turns`    | 20     | 原文保留最近多少轮发给大模型                     |
| `summarize_batch` | 6      | 攒够几轮才压一次摘要（调大 = 更省 API 调用）         |
| `verbosity`       | normal | 回复长短：`terse` / `normal` / `chatty` |

> 摘要长得什么样，网页上聊天区顶部会显示一行「🧠 长期记忆：……」，看得见。  
> 想快速看到效果：点记忆面板里的「**立即整理记忆**」，不用等窗口溢出。
> 或者把 `memory_turns` 调成 1、`summarize_batch` 调成 2，聊三四轮就自动出来了。

## 记忆面板（🧠 按钮）

顶部「🧠 记忆」按钮，打开当前角色的记忆面板：

- **摘要可读可改** —— 直接编辑那句话，保存后立刻生效。  
  比如你手动写成「玩家欠我 20 金」，下次对话角色就会提起这笔账。
- **立即整理记忆** —— 不用等窗口溢出，点一下就把当前对话压成一句长期记忆。
  聊到关键剧情（"玩家答应帮我找石头"）时可以马上固化，不怕以后被挤掉。
- **看得到底有多少历史** —— 「完整历史 32 条（7 轮）· 只发最近 20 轮 · 攒 6 轮压一次摘要」
- **清空摘要** —— 只忘掉长期记忆（窗口外的老对话），最近几轮仍然记得

对应接口：

| 方法   | 路径                                | 说明                                                        |
| ---- | --------------------------------- | --------------------------------------------------------- |
| GET  | `/memory?mode=npc&npc=blacksmith` | 读某个角色的记忆信息                                                |
| POST | `/memory`                         | 手动写摘要 `{"mode":"npc","npc":"blacksmith","summary":"..."}` |
| POST | `/memory/compress`                | **立即整理**：把当前对话压成摘要 |
| POST | `/memory/clear`                   | 只清长期记忆（保留最近窗口）                                            |

> 摘要会吸顶显示在聊天区顶部，随时看得见角色"记得什么"。

## 整包备份 / 恢复

想换电脑、备份、或者存档一份完整状态 —— 打包整个项目。

**网页上**：

- 「存档」→ 弹窗右上角「📦 **整包备份**」→ 直接下载 zip
- 「📥 **导入备份**」→ 选一个 zip → **整包恢复**（会二次确认，恢复后自动刷新页面）

**命令行**：

```bash
python backup.py                    # 打包到 backups/（不含 API key）
python backup.py --with-key         # 连 .env 一起打（含密钥，注意保密）
python backup.py --list             # 列出已有备份

python backup.py --restore X.zip        # 先预览会覆盖哪些文件（不写入）
python backup.py --restore X.zip --yes  # 确认后真的恢复
```

**包里有什么**（约 40 个文件）：

```
✅ 代码      *.py
✅ 角色数据  characters.json / settings.json
✅ 存档      saves/*.json（对话历史 + 摘要 + 金币血量）
✅ 头像      web/avatars/*
✅ 界面      web/index.html
✅ 示例      game_clients/*
✅ 说明      README.md / requirements.txt / .env.example
📄 backup.json   ← 清单（时间、版本、文件数）

❌ .env       默认不含，API key 不会跟着走（除非加 --with-key）
❌ backups/   __pycache__/  .DS_Store   自动跳过
```

**恢复是安全的**：默认只**预览**（列出会新增/覆盖哪些文件），要加 `--yes` 才真写。
解压路径也做了防穿越检查，不会写到项目目录外面。

## 📤 单角色备份（只导一个角色）

角色管理那一行点「**导出**」，会把**这个角色**打成一个几 KB 的小 zip（约 3 KB）：

```
character-chiaya.zip
├── single-character.json     ← 角色定义（性格、价目表、说话长短、记忆窗口）
├── avatars/chiaya.svg        ← 头像
├── avatars/chiaya-happy.svg
├── avatars/chiaya-angry.svg
└── save.json                 ← 你和这个角色的对话记忆（如果有）
```

**导入时会自动识别**是单角色包还是整包备份：

| 情况 | 效果 |
|---|---|
| 角色不存在 | 直接导入 |
| 角色已存在 | 弹三个按钮：**覆盖** / **另存为** / 取消 |

- **覆盖** = 替换掉现在的同名角色（保留它在列表里的位置）
- **另存为** = 两个都留着，自动改名（千绫 → 千绫 2），头像一并改名

适合：把某个角色分享给朋友、单独备份自己调好的角色、在另一台机器上补一个角色。

**整包 vs 单角色**：

| | 整包备份 | 单角色备份 |
|---|---|---|
| 内容 | 全部角色 + 代码 + 全部设置 | 一个角色 |
| 大小 | ~74 KB | ~3 KB |
| 用途 | 换电脑 / 灾难备份 | 分享 / 单独备份 |

**命令行也有**：

```bash
python -c "import backup;open('c.zip','wb').write(backup.build_character_zip('chiaya'))"
```

## 体检：`python selftest.py`

不用 API key，一次跑完全部离线检查：


```
— 测试智能体循环 —       工具调用 + 上下文顺序
— 测试 NPC 改游戏状态 —   买卖、钱不够拒绝、回血、变化量
— 测试记忆窗口与摘要 —    窗口裁剪、摘要生成、存档读档、手动整理
— 结构体检 —            放错位置 / 重复定义 / 死代码
```

**结构体检**（`healthcheck.py`）专门抓一类很隐蔽的 bug —— 代码被插到类中间把类截断了。
这种错误**语法是合法的**，但会让整个 HTTP 服务瘫痪（所有 POST 返回 501）。它检查：

| 检查项 | 抓什么 |
|---|---|
| 模块级函数第一个参数是 `self` | 本该是类的方法，却掉到了外面 |
| 函数里嵌套定义 `do_xxx` / 带 `self` 的函数 | 类被截断了（**当初 501 的元凶**） |
| `Handler` 类是否缺 `do_GET` / `do_POST` | 类不完整 |
| 类里重复定义同名方法 | 复制粘贴事故 |
| 模块级重复定义 | 同上 |
| 死代码（全项目没人引用的函数/类/变量） | 半成品残留 |
| JS 重复定义 / 引用了不存在的元素 id | 前端同类问题 |

只想单独跑体检：`python healthcheck.py`（有问题会返回退出码 1）。

## 想加新能力？

在 `tools.py` 或 `tools_extra.py` 里写个普通函数，用 `Tool(...)` 包一层就行。  
工具的 `description` 写清楚「什么时候用」，模型就会在需要时调用它。

## ⚠️ 安全

- **工具参数不可信**：模型可能传错值，`Tool.run` 已做兜底，但涉及删文件/扣钱/执行代码的，务必在函数内部自己再校验。
- **文件工具关在沙箱**：只能操作 `workspace/` 目录，出不去。
- **执行代码默认禁用**：要开先设 `ENABLE_CODE_EXEC=1`，且仅限本地自用，别对外暴露。
- **循环有上限**（`max_steps=6`），防止死循环烧钱。
